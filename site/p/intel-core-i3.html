I had a somewhat dodgy stick of used RAM (DDR4 UDIMM) in a Supermicro X11 board. This board is running my NAS, all ZFS, so RAM corruption can equal data corruption. The OS alerted me to recoverable errors on DIMM B2. Swapped it and another DIMM, rebooted, saw DIMM error on slot B1. Swapped it for a spare stick. No more errors. This was running at like, 1866 or something. It's a pretty barebones 8th gen i3 with a beefier chipset, but ECC still came in clutch. I won't buy hardware for server purposes without it.

I built my own NAS for a total cost of £1000. 24TB physical drives, 16TB useable (Raid Z2). It runs Ubuntu LTS server edition and I spin up any containers I need in Docker using Portainer. Is it a point and click GUI that is friendly to all? No ... I have to manually create SMB mounts and the like in the terminal, but it's easy enough to keep running. Hardware wise it's: - Asrock Rack C246 WSI Mini ITX motherboard - 32GB ECC RAM (2x 16GB UDIMMS) - benefit of using the C246 chipset - Intel i3-9100T - 6 IronWolf 4TB NAS drives - 2U Short Depth rackmount chassis (so it fits in my network rack) - 1TB Samsung 850 Evo boot drive Idles at 23W which is low enough for my tastes, ramps up to 65W under load (I spin the disks down after 10 minutes of inactivity, even doing that I'm only seeing about 10k load/unload cycles a year (drive is rated for 600k).
